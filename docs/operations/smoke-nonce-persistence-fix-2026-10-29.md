# 本地烟雾测试防重放记录保存修复 — 2026-10-29

## 根因与范围

本地运维脚本 `scripts/test-research-cloud-smoke.mjs` 将已验证响应的 nonce 写入临时文件，再用 `rename` 替换正式账本。旧实现只替换一次；Windows 偶发拒绝替换后，认证层将文件错误归为认证不可用，导致测试提前退出。固定的 `<key>.<pid>.tmp` 名称还会让残留文件阻塞同一进程的后续调用。

本次在 Windows、Node 24.14.1 上直接运行原函数，分别在第177次和第422次迭代后捕获 `EPERM`、errno `-4048`、syscall `rename`。第二次失败后，对同一临时文件再次执行替换约3.35ms成功。证据确认短暂的替换拒绝；没有证据判断由哪个进程或系统组件引起，不能归因于某一杀毒软件。原5秒操作预算不是这两次失败的原因。

受影响范围是本地烟雾测试/运维脚本；本次不修改网站页面、Worker、数据库或模型调用，不需要正式站部署。

## 修复约束

- 仅对 Windows 下替换操作的 `EPERM` 重试，最多5次，间隔20/40/80/160ms；其他错误立即失败。
- 重试期间始终持有原互斥锁，保留完整临时文件和原账本。每次重试检查现有期限；5秒/10秒上限不变，不重发业务请求。
- 临时文件加入独立UUID。显式取得文件所有权后才负责清理，写入失败也关闭句柄、清理本次文件和释放自己的锁。不会清理其他调用的锁或历史临时文件。
- 只有保存成功、期限检查及认证均通过后才接受响应；重复响应仍被拒绝。
- 报告按需添加最多16条 `nonceStorage` 诊断，仅记录固定阶段、白名单错误码、次数和恢复状态。原始异常消息、文件路径、nonce及密钥不进入诊断。
