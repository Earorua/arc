# Arc. v8 整站完成四目标流程规格

**日期：** 2026-08-24

**状态：** 书面规格与目标 1 详细实施计划已获用户批准；目标 1 按方式 1 执行中

**基础提交：** `9128321575a67c2fc6ec86e2ce1924e631ba28fe`

**公开生产：** Arc. v7.2 / Sites version 9

**Sites 项目：** 复用现有 `.openai/hosting.json` 中的项目及逻辑 `DB`、`PROOF_ASSETS` 绑定

## 1. 目的

本规格把 Arc. v8 从已完成的 Phase 1–2 推进到完整公开产品所需的剩余工作，拆成四个可连续执行数小时、能够独立验收和回滚的目标：

1. Proof-backed Stack；
2. OpenRouter Research Beta；
3. Production Candidate；
4. Public Release & Stabilization。

目标数量固定为四个。Phase 3、Phase 4、发布候选和生产发布分别隔离，避免把 Proof 数据模型、外部 AI、生产迁移和公开流量切换混在一个不可控的大目标中。

## 2. 当前权威基线

- Phase 1 `Trusted Intelligence Kernel` 已完成并合并。
- Phase 2 `Adaptive Planning Loop` 已完成工程建设、本地用户验收、本地合并和 GitHub 远程备份。
- 本地 `master` 与 `origin/master` 当前均为 `9128321575a67c2fc6ec86e2ce1924e631ba28fe`。
- `drizzle/0002_product_intelligence.sql` 与 `drizzle/0003_adaptive_planning.sql` 尚未应用到生产 D1。
- Live Research Beta 尚未启用，也未配置或读取生产 OpenRouter 密钥。
- 当前公开站点仍运行 Arc. v7.2 / Sites version 9；本规格不授权任何生产迁移、运行时配置修改、功能旗标修改或公开部署。

## 3. 整站完成定义

只有同时满足以下条件，Arc. v8 才能标记为“整个网站搭建完成”：

- 路线图 Phase 1–5 全部通过各自退出门槛；
- 公开 Sites URL 正在运行获批的 v8 精确产物；
- Flagship 确定性闭环与 Research Beta 均按权限边界工作；
- Proof-backed Stack 的技能状态可以追溯并能在证据撤销后重算；
- v7.2 登录、退出、账户关联、账户隔离、设备迁移、D1、R2 和 Proof 隐私无回归；
- 手机、桌面、键盘与辅助技术核心路径通过；
- 模型成本、速率限制、停用开关、日志、告警、备份和回滚能力齐备；
- 本地 Git、GitHub、Sites、恢复检查点和发布记录状态一致；
- 用户明确完成公开生产验收。

任何单个目标完成、候选版本保存或本地验收通过，都不能提前宣称整站完成。

## 4. 跨目标执行协议

### 4.1 每个目标的标准流水线

每个目标按以下顺序执行：

1. 读取本规格、v8 路线图、相关已批准规格和上一目标检查点；
2. 刷新 GitHub 引用，确认本地与远端基线，没有未处理的用户改动；
3. 创建独立 `codex/` 分支与 `.worktrees/` 工作树；
4. 根据当时真实文件、类型和服务契约编写该目标的详细实施计划；
5. 使用 TDD 执行：判别性失败测试、最小实现、聚焦回归、可回滚提交；
6. 运行相邻高风险回归与完整工程门槛；
7. 完成代码、数据、安全、隐私和可访问性审查，修复后重新验证；
8. 启动本地或候选环境，完成该目标规定的人工验收；
9. 更新完成记录与恢复检查点；
10. 只在目标授权范围内合并、远程备份或保存 Sites 候选；
11. 确认提交已保留后清理阶段工作树。

### 4.2 持续执行规则

- 用户启动一个目标后，普通实现选择、测试失败、可恢复工具错误和常规代码审查不构成暂停理由；执行者应定位根因、修复并持续到退出门槛。
- 每个目标允许包含多个内部任务和提交，但不把内部任务升级为额外用户目标。
- 至少每 60 分钟提供一次简短进度；重要门槛、风险变化或外部状态变化立即报告。
- 不因上下文压缩、开发服务器退出或单次网络失败从头重做已完成工作；使用 Git、计划复选框和恢复检查点继续。
- 不修改无关用户文件，不使用 force push，不重写既有生产迁移。

### 4.3 强制暂停条件

只有以下情况要求用户提供新授权或决定：

- 生产 D1/R2 写入或生产数据恢复；
- 创建、读取或使用真实付费模型密钥及真实模型请求；
- 修改生产运行时变量、功能旗标、访问范围或公开流量；
- 外部系统状态与批准方案冲突，继续会覆盖他人变更；
- 实现证据要求改变已批准的产品语义、隐私边界或付费范围；
- 无法安全推断的用户身份、账户归属或数据保留决定。

## 5. 目标 1 — Proof-backed Stack

### 5.1 目标

完成 Phase 3，使学习事件、Proof 和技能状态形成可追溯、可撤销、可重算的证据闭环。

### 5.2 工作范围

- 对齐远程备份后的文档与恢复状态；
- 编写基于现有事件、Proof 和身份契约的 Phase 3 详细计划；
- 增加 Proof 版本与审核状态机；
- 实现技能证据聚合和 `exploring / practicing / demonstrated / verified` 状态；
- 明确学习单元完成只能推进自评或提交状态，不能自动授予 `verified`；
- Proof 拒绝、撤销、替换或私有化后确定性重算相关技能状态；
- 安全兼容旧 `proof_items.verified`，不反向污染新状态机；
- 升级 Proof、Stack、Today 和公开 Proof 快照；
- 公开数据继续使用获准字段快照，不泄漏邮箱、内部 ID、私有对象键或 AI 输入；
- 新迁移保持 additive，并通过本地 D1 smoke 与静态约束测试。

### 5.3 验证重点

- 相同事件与 Proof 序列产生相同技能状态；
- 跨账户、跨目标和跨公开 token 不能读取他人证据；
- 撤销或拒绝证据会降低或重算状态；
- 旧 v7.2 Proof、上传和分享行为无回归；
- 手机、桌面、键盘与状态公告可用；
- 单元、集成、渲染、TypeScript、ESLint 和生产构建全部通过。

### 5.4 退出门槛与授权边界

目标完成包括：本地人工验收、独立审查、本地合并、GitHub 普通推送和阶段清理。目标不包括生产 D1 迁移、R2 生产写入、Sites 候选保存或部署。

**启动口令：** `执行目标 1：完成 Proof-backed Stack，持续到本地验收、合并和远程备份，不部署。`

## 6. 目标 2 — OpenRouter Research Beta

### 6.1 目标

完成 Phase 4，为非 Flagship 岗位提供带来源、质量门槛、预算保护和确定性降级的受控实时研究。

### 6.2 工作范围

- 编写基于最终 Phase 3 类型的 Phase 4 详细计划；
- 建立仅服务端可见的 OpenRouter provider 接口与固定任务模型策略；
- 实现来源获取、规范化、去重、覆盖率和置信度评估；
- 使用严格结构化输出，最多允许一次受控修复；
- 实现账户、IP、时间窗口、任务与全站预算限制；
- 实现缓存、幂等、并发去重和可审计的调用元数据；
- 实现 `Researching / Needs review / Ready / Failed` 状态及可恢复边界；
- 无来源、低置信度、超预算或不合格结果不得进入正式路线；
- OpenRouter 未配置、超时或失败时，Flagship 确定性路径保持完整；
- 密钥、完整提示、私密输入、provider 原始错误和内部成本数据不得进入客户端、D1 公共字段或日志。

### 6.3 验证重点

- 未登录或未获准用户不能触发付费请求；
- 重复请求幂等，失败不错误消耗已接受配额；
- 不合格结果保持草稿或失败状态；
- 无真实密钥契约测试覆盖全部失败模式；
- 经单独授权后只做预算有界的最小真实请求验证；
- 产物扫描确认没有密钥、模型凭据或浏览器可读 provider 边界。

### 6.4 退出门槛与授权边界

目标完成包括：本地人工验收、独立审查、本地合并、GitHub 普通推送和阶段清理。真实密钥创建/读取、付费请求、生产变量和生产旗标必须在目标执行时获得独立明确授权；没有该授权时，目标停在真实请求门槛，不能虚构线上证据。目标不包括生产部署。

**启动口令：** `执行目标 2：完成 OpenRouter Research Beta，持续到本地验收、合并和远程备份；真实模型请求前单独确认。`

## 7. 目标 3 — Production Candidate

### 7.1 目标

完成 Phase 5 的发布候选部分，把全部 v8 源码、迁移、配置和验证证据组装成可发布但尚未替换公开流量的精确 Sites 版本。

### 7.2 工作范围

- 读取现有 Sites 项目、公开访问策略、逻辑 D1/R2 绑定、OAuth 和运行时配置；
- 逐份审核 `0002`、`0003` 及 Phase 3–4 新增迁移，不改写已存在迁移；
- 在隔离数据库上从生产兼容基线预演完整迁移；
- 验证现有用户、身份、目标、进度、Proof、分享状态和设备迁移数据完整；
- 建立迁移前备份、失败检测、恢复和回滚操作说明；
- 将当前 Arc. v7.2 / Sites version 9 固定为 v8 发布后的立即回滚候选；保留更早稳定版本作为深层恢复证据；
- 验证 Google/GitHub 登录、退出、重新认证、账户关联、账户隔离和设备迁移；
- 验证 D1 持久化、R2 私有资产和公开 Proof 快照；
- 验证访客 Flagship、登录用户规划、Proof-backed Stack 和 Research Beta；
- 验证 OpenRouter 关闭、超时、超预算和失败降级；
- 完成安全、隐私、可访问性、响应式、成本和可观测性审计；
- 完成管理员停用、功能旗标、预算告警、健康检查和日志策略；
- 构建、打包并保存与已验证 Git 提交一致的 Sites 候选版本；
- 在不改变公开生产流量的环境完成候选验收。

### 7.3 验证重点

- 完整单元、集成、渲染、TypeScript、ESLint 和五阶段生产构建；
- 迁移静态断言、本地 D1 smoke、升级与兼容回归；
- 客户端、构建产物、日志和错误消息的 secret/privacy 扫描；
- 手机与桌面全链路人工验收；
- 保存版本的提交哈希、文件树、迁移和 hosting metadata 与验证对象一致。

### 7.4 退出门槛与授权边界

目标完成时，新 Sites 候选版本已保存并可定位，生产 D1 与公开站点仍保持原状态。保存候选不授权执行生产迁移、改变生产旗标或部署到现有公开访问范围。

**启动口令：** `执行目标 3：完成 v8 Production Candidate，持续到保存未公开的 Sites 候选版本，不切换生产流量。`

## 8. 目标 4 — Public Release & Stabilization

### 8.1 目标

在明确生产授权、可恢复数据迁移和精确候选产物基础上，将 v8 发布到现有公开 Sites 项目，并完成生产稳定化与用户验收。

### 8.2 工作范围

- 重新读取 Sites、GitHub、D1/R2、访问策略和候选版本状态，排除外部漂移；
- 在迁移前取得并验证生产数据备份；
- 按预演顺序执行获批的 additive 生产迁移；
- 迁移后验证表、索引、约束、行数、账户归属和关键记录连续性；
- 以安全默认旗标部署精确候选产物；
- 在公开流量切换前展示解析出的实际访问范围，并获得最终公开部署批准；
- 轮询部署状态直至成功或明确失败；
- 验证首页、Setup、Build、Path、Today、Proof、Stack、身份、规划重排、跨刷新持久化和 Research Beta；
- 检查 Worker 错误、认证异常、D1/R2 异常、预算、限流和健康指标；
- 阻断级故障触发立即回滚，普通 provider 失败按 Flagship 降级处理；
- 完成用户生产验收并更新 README、发布记录、恢复检查点和回滚证据；
- 提交并远程备份最终记录。

### 8.3 发布与回滚规则

- 生产 D1 迁移、运行时变量、功能旗标和公开 Sites 部署分别是外部写入门槛；执行前必须确认当时的准确目标和影响。
- 不使用 force push，不改变生产 slug，不删除旧 Sites 版本。
- 公开部署失败时不打开失败版本；保留当前公开版本并报告可操作原因。
- 数据完整性、身份隔离、私有 Proof 泄漏或核心路由不可用属于立即回滚条件。
- OpenRouter 单独失败但 Flagship 正常时，关闭 Research Beta 旗标，不必自动回滚整个站点。

### 8.4 退出门槛

- 公开 URL 正在运行获批 v8；
- 生产数据、身份和旧用户进度完整；
- 核心路径人工与自动冒烟通过；
- 阻断级日志为零，成本与限流可观测；
- 回滚版本仍可部署；
- 用户明确确认生产验收通过；
- GitHub、Sites 与恢复文档状态一致。

**启动口令：** `执行目标 4：完成 v8 公开发布与稳定化；生产迁移和公开切换按计划中的强制批准门槛执行。`

   ↓

   ↓
目标 1：Phase 3 Proof-backed Stack
   ↓
