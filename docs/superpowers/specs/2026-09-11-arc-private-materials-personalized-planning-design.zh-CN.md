# Arc 多资料导入与个性化方案设计

> 文档版本：v1.0 设计草案  
> 日期：2026-09-11  
> 范围：产品体验、技术架构、数据模型、规划规则、交付阶段及验收标准。  
> 本次交付：仅新增本 Markdown 文档，不修改源码、配置或数据库，不执行部署及模型调用。  
> 文中“应”“必须”和参数上限均为拟实施要求，不代表当前系统已经具备这些能力。

## 1. 推荐方案与目标

采用“私人资料库 + 结构化信息提取 + 用户确认 + 确定性规划”的方案。

用户可以导入个人简历、目标公司岗位 JD、项目说明、学习记录及面试反馈。系统从资料中提取可核对的信息，结合已有技能自评、Proof 和时间安排，生成更贴合个人现状及目标要求的学习路线。

核心价值应体现在实际方案变化：减少重复学习，优先处理岗位必备技能缺口，为已有经历安排合适的能力校准，为薄弱环节安排可执行的实践任务，并说明每项调整的依据。

### 1.1 设计默认值

以下作为完整方案的默认设计，尚未获得用户逐项确认：

- 资料存入登录用户的私人资料库，可在后续不同目标中复用。
- 每个目标显式选择资料，不自动读取资料库中的全部内容。
- 首版每个目标最多关联 1 份主简历、1 份主 JD 和 3 份补充资料；可以缺少简历或 JD，也可以完全跳过导入。
- 同一份简历可以关联不同目标；不同公司、岗位的 JD 分别用于独立目标。
- 首版只有当前目标编辑流程；并列比较、批量切换多个目标作为后续工作。
- 上传到云端与发送给外部模型是两个不同步骤。外部模型分析需要明确说明处理方和用途。
- 更新资料产生候选调整，不直接替换正在执行的计划。

### 1.2 首版不包含的能力

- 自动投递简历、联系招聘人员、代替用户做招聘决策。
- 自动证明简历真实、自动授予技能验证状态或预测录用概率。
- 任意网页、私有仓库、网盘和招聘平台账户抓取。
- 图片 OCR、音视频转录、旧式 DOC/XLS 文件解析。
- 面向所有文件的通用问答系统、全量向量知识库。
- 无资料支撑的技能补全、未经验证的新学习单元自动发布。

## 2. 当前项目基础及接入边界

本方案依据当前工作区代码设计，不推断生产部署已经具备相同能力。

| 当前基础 | 可以复用的部分 | 需要新增的部分 |
| --- | --- | --- |
| Setup 的技能自评、可用时间及目标步骤 | 已有输入与确认流程 | 可选资料导入、结果核对、资料选择 |
| 岗位蓝图与学习单元注册表 | 已验证技能、依赖、资源和任务 | JD 要求映射及未覆盖项展示 |
| 路径构建与日历排程 | 确定性的任务选择、依赖和时间约束 | 私有规划上下文及岗位优先级输入 |
| 计划版本、事件和差异确认 | 新旧方案比较及接受/放弃模式 | 资料变化触发的候选调整 |
| D1、私有 R2 和账户会话 | 持久化及所有者校验模式 | 资料独立实体、任务记录与存储命名空间 |
| 受控模型服务的额度和预算模式 | 鉴权、限流、预算预留及脱敏观测模式 | 独立资料分析任务类型和输入契约 |

重要边界：

1. 现有研究 Provider 的输入是岗位及语言。简历、个人经历和私人 JD 不应塞进岗位名称字段。
2. 现有 `research_packages` 定位为非个人研究缓存。个人资料、确认结果及个性化上下文必须存入所有者隔离的私有存储。
3. 现有技能自评中的证据引用为公共链接等元数据，不能把私有文件地址伪装为公共证据链接。
4. 私有资料引用使用新的 `sourceRef`；资料导入不改变 Proof 的验证或公开状态。
5. 现有独立掌握自评可以触发校准任务，但其他自评等级不代表系统已经支持所有细粒度课程跳过策略。
6. 当前可确认的托管配置包含 D1、R2；不能据此认定后台队列、OCR 或文件解析运行时已经可用。

## 3. 技术路线比较

| 路线 | 适用情形 | 优点 | 代价 | 本方案选择 |
| --- | --- | --- | --- | --- |
| 结构化提取 + 明确规则规划 | 简历、JD、少量补充材料 | 可编辑、可追溯、易复用，规划可重现 | 需要字段、映射和版本契约 | 首版采用 |
| 每次把全文交给模型生成方案 | 快速验证交互原型 | 初始链路短 | 重复模型消耗、变化难解释、难保证任务合法 | 不作为正式规划主链路 |
| 结构化数据 + RAG 检索 | 长资料较多，开始需要跨文件问答 | 按需取回细节，支持资料问答 | 增加切块、索引、检索评估和权限维护 | 第三阶段按实际需求增加 |

文件解析器和模型通过适配器隔离。具体 PDF/DOCX 解析库与模型型号在可行性验证后选择，不在设计阶段假设某个库可以直接运行于当前边缘环境。

## 4. 资料类型与结构化内容

| 类型 | 主要字段 | 对规划的作用 | 必须保留的解释边界 |
| --- | --- | --- | --- |
| 简历 | 经历、项目、技能、教育、时间范围、个人职责 | 建议自评、发现可校准能力、减少重复学习 | 团队使用某技术不等于用户独立掌握 |
| JD | 公司、岗位、职级、职责、必备项、加分项、经验及教育要求 | 设置目标、缺口和优先级 | JD 是该岗位要求，不能自动推广为行业共识 |
| 项目说明/作品集 | 项目目标、个人贡献、技术场景、成果、相关链接 | 推荐校准及作品补强方向 | 上传文件或链接不等于完成独立审查 |
| 学习记录/证书 | 内容范围、完成时间、课程或考试类型 | 建议复习范围和校准起点 | 修读或获证不自动等于能独立实践 |
| 面试反馈 | 问题、反馈、发生时间、相关岗位 | 提出近期补强建议 | 个别反馈保留来源及适用范围 |
| 补充说明 | 时间约束、偏好、目标说明、主动修正 | 更新目标与排程约束 | 用户手动输入明确标为用户补充 |

首版对简历与 JD 提供专门字段；其他资料使用通用“经历/要求/反馈条目 + 来源片段”结构，不承诺每种补充材料都有完整专用解析器。

### 4.1 文件格式与初始限制

以下是可配置的首版产品默认值，不是对平台能力或处理时延的保证：

| 项目 | 默认设计 |
| --- | --- |
| 文件格式 | 文本型 PDF、DOCX、UTF-8 TXT、Markdown |
| 文本输入 | 可直接粘贴简历、JD 或补充说明 |
| 单文件大小 | 最多 5 MiB；资料规则独立定义，不修改 Proof 上传规则 |
| PDF 页数 | 最多 20 页 |
| DOCX | 限解压后总量 20 MiB、条目数 1,000；不把缺少稳定页码的 DOCX 强行标页 |
| 提取文本 | 每份最多 50,000 字符；超限需用户缩小范围，不能静默截断 |
| 资料库配额 | 首版最多 30 份资料、100 MiB 原文件，替换版本也计入配额 |
| 目标关联 | 最多 5 份启用资料 |
| 同时处理 | 每用户最多 2 个文件提取任务、1 个模型分析任务 |
| 加密/扫描文件 | 明确提示不支持，提供重新导出或粘贴文本路径 |

页数、字符数和压缩包限制仅是第一层。模型调用还需要独立的 token、输出长度、时限和费用上限，不能用字符数代替 token 预算。

## 5. 用户体验与页面流程

### 5.1 新建方案

```text
选择岗位或目标
  → 可选：导入/选择资料
  → 查看提取文本，决定哪些内容发送给模型
  → 分析资料，或手动填写结构化字段
  → 核对个人信息与岗位要求
  → 完成技能自评、可用时间及目标期限
  → 查看差距、路线范围和生成依据
  → 确认保存计划
```

用户跳过资料步骤时，进入原有流程。导入某份资料失败时，可以移除该资料继续，不阻塞其余已确认资料的使用。

### 5.2 资料库

每条资料展示名称、类型、版本、更新时间、处理状态和关联目标。提供上传、替换、查看、编辑确认结果、解除目标关联和彻底删除操作。

资料库中保存不等于自动参与当前方案。用户必须选择具体资料和版本；使用新版本时提示其对当前方案的影响。

### 5.3 文本检查与结果核对

文本检查页展示服务端确定性提取的正文，允许删除无关内容；联系方式等常见信息提供辅助遮蔽，但提示用户自行复核。

结果核对页按资料类型展示简历经历、JD 要求和补充信息。每个条目可以查看原文、修正、确认或忽略；只要求处理会影响当前方案的歧义和冲突，避免让用户逐字确认全部原文。

用户确认的是“采用这一信息”，不是“系统已经验证这项能力”。能力等级仍需在技能自评或校准流程中明确。

示例：

> 简历原文：“参与基于 React 的后台系统开发。”  
> 已识别：有 React 使用经历。  
> 待确认：你负责了哪些功能，是否能够独立完成类似任务？

> JD 原文：“熟练使用 SQL，具备 Python 数据处理经验者优先。”  
> 已识别：SQL 为必备项，Python 为加分项。  
> 采用后：在依赖和时间约束允许的范围内，优先安排 SQL 缺口。

### 5.4 生成结果

结果展示四类信息：目标要求、当前能力判断、拟安排任务、调整依据。支持从计划任务回到资料原文。

不展示缺少校准依据的“岗位匹配率”“录用概率”或模型置信度百分比。可以展示明确可解释的计数，例如“8 项必备要求中，5 项已有路线覆盖、2 项需要核对、1 项当前未覆盖”，并说明覆盖不等于掌握。

### 5.5 更新已有计划

首版更新资料后标记“资料已更新”，允许重新生成并预览候选；如尚不支持跨版本连续重排，应明确创建新计划，不能悄悄重置学习进度。

第二阶段支持基于当前计划版本生成调整建议，展示新增、移除、顺序及预计完成时间变化。接受前保持现有计划可用；放弃候选不删除资料和历史记录。

## 6. 信息提取、来源与冲突规则

### 6.1 两段处理

第一段是确定性文件提取：检查文件、读取文本、保留段落位置。上传操作允许此处理，但不隐含允许外部模型接收正文。

第二段是可选模型分析：仅处理用户确认的文本版本，输出受约束的结构化候选。模型不可用或用户不愿发送时，提供手动录入同类字段的路径。

首版每份资料独立分析，之后通过规则合并已确认字段，避免为每次生成计划重新发送全部文件。

### 6.2 每项事实的来源契约

每项候选包含稳定条目 ID、条目类型、原始表述、标准化值、资料版本、文本片段 ID、确认状态和映射状态。

来源位置由解析器产生。PDF 使用可提取的页码和文本块；DOCX 使用段落/表格路径；TXT 与 Markdown 使用行或字符范围。不能可靠定位时只显示原文片段，不虚构页码。

模型引用已有片段 ID，服务端验证引用存在且属于本次输入。引用存在只证明原文可定位，不能自动证明模型解释正确；高影响解释仍需用户核对。

用户改写候选时保留原提取结果，并新增用户修正版本。手动添加的信息标为“用户补充”，不得伪造为文件原文。

### 6.3 语义与冲突

| 情形 | 处理规则 |
| --- | --- |
| 文件未提到某技能 | 标记缺少信息，保留当前自评；不判定用户不会 |
| 提及工具但未说明职责 | 只生成使用经历线索，不赋予独立掌握等级 |
| 简历与用户当前自评冲突 | 展示冲突，采用用户本次明确确认的自评 |
| 用户自评与现有 Proof 不一致 | 分别展示来源与时间，不删除 Proof，不自动升级或降级验证状态 |
| 多版简历时间或职责不同 | 不以最新上传时间判定真实性，要求选择当前适用版本 |
| 同一 JD 同时出现矛盾要求 | 标记冲突，确认前不将该条目作为硬性规划约束 |
| 主 JD 与其他资料优先级冲突 | 以用户确认的主目标要求为准，保留补充资料的不同表述 |
| “了解”“熟悉”“精通”等模糊措辞 | 保留措辞，结合岗位任务提问；不直接映射成固定数字等级 |

时间字段区分“资料上传时间”“经历发生时间”“JD 发布或用户确认时间”，缺少发布日期时显示未知，不把上传时间冒充发布日期。

## 7. 技能映射与差距分析

### 7.1 映射流程

1. 根据技能名称与受控别名表生成确定性候选。
2. 利用上下文区分同名、近义、上下位概念。
3. 对歧义映射展示候选，由用户选择或暂不采用。
4. 将已确认映射绑定到确切岗位蓝图及版本中的技能 ID。
5. 无法映射的要求进入未覆盖清单，不插入未经验证的技能和任务。

模型可以提出映射建议，但不能创建既有蓝图中不存在的技能 ID，不能修改全局技能目录。映射必须通过字段、所有权和蓝图成员校验。

### 7.2 差距状态

差距采用分类状态，避免把未知信息压缩成一个分数：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 已有相关经历，待校准 | 有经历线索但未确认独立能力 | 完成自评或短校准 |
| 已确认需要学习 | 用户明确不熟悉或已有有效校准发现缺口 | 安排学习与实践 |
| 信息不足 | 无足够资料或自评 | 补问或校准 |
| 需要成果补强 | 知识相关，但缺少可展示任务成果 | 选择已有合适作品任务 |
| 当前路线未覆盖 | JD 要求未映射到完整可执行技能轨道 | 展示限制，后续研究补齐 |
| 非学习型要求 | 学历、工作年限、地点等 | 单独展示，不虚构为学习任务 |

岗位必备/加分属性与能力状态分别存储。例如“SQL 是必备项”不代表“SQL 是用户缺口”，还要结合用户确认的能力信息。

## 8. 个性化规划规则

### 8.1 规划输入

规划上下文由服务端构建，包含以下版本化输入：

- 已验证的岗位蓝图和学习单元注册表。
- 当前目标采用的资料版本、确认版本和技能映射版本。
- 用户明确确认的技能自评，以及按现有语义可用的 Proof 引用。
- 主 JD 中确认采用的要求、重要性和未覆盖清单。
- 时间安排、目标期限、已完成单元与相关学习事件。
- 规划策略、映射策略和解释模板的版本。

原文件全文不进入排程器。排程器只消费经过校验的结构化输入。

### 8.2 排序与范围规则

采用分层决策，不在首版设置难解释的综合权重分数：

1. 先保证任务合法、前置依赖成立、时间预算不超限，并保护已完成记录。
2. 展开目标必备技能及其前置依赖，识别不可省略的学习或校准任务。
3. 在当前可执行的任务之间，优先处理岗位必备项中的已确认缺口。
4. 再处理重要但能力不明的校准任务、职责相关实践和加分项。
5. 使用已有稳定顺序及技能 ID 作为平局规则，保证同输入结果一致。

“优先级高”不能绕过依赖，也不能保证在任意截止日期内完成。目标期限不足时，展示完整范围的预计时间，以及期限内可完成的部分和明确延期项。

### 8.3 经历如何影响任务

| 信息 | 规划行为 |
| --- | --- |
| 只有简历中的使用经历 | 预填经历说明、建议用户确认自评，不自动跳过学习 |
| 用户确认能够独立完成相关任务 | 按现有规划语义选择校准任务 |
| 校准发现缺口 | 使用现有合法补强单元；没有对应单元则展示缺口 |
| 用户明确缺少岗位必备技能 | 在依赖允许时提高对应学习任务优先级 |
| 已有知识但希望增加作品 | 在已验证注册表中选择目标相关任务 |
| JD 提到现有目录外的技能 | 显示未覆盖，不生成伪装为完整路线的任务 |

首版不保证细分到“某课程的某一节可以跳过”。更细粒度的裁剪需要单元级先修、掌握条件和校准结果契约。

### 8.4 JD 个性化与公共岗位蓝图

保留原岗位蓝图及版本，新增私有目标要求覆盖层，用于优先级、范围和解释。该覆盖层不覆盖公共蓝图内容，也不写入公共研究缓存。

若未来需要加入目录外技能，应生成私有候选扩展，补齐技能定义、依赖、资源及学习单元，经过现有领域验证后才可参与规划。未经允许，不向联网研究发送个人简历或私人 JD；后续研究只能使用用户确认可发送的非个人查询。

### 8.5 解释结果

每项个性化调整包含：调整类型、涉及任务、依据条目、规则版本、对时间和范围的影响。

调整说明优先由结构化结果与模板生成，不为每次生成额外调用模型。示例：

> 将 SQL 学习任务提前：你确认的主 JD 将 SQL 列为必备项，且本次自评显示需要补强；相关前置任务仍保留。

> 将 React 基础学习替换为校准：你本次确认能够独立完成 React 任务。简历项目用于解释经历来源，不作为系统验证结论。

## 9. 系统架构与模块契约

```text
资料库 / Setup / 计划差异页面
                  │
             会话与权限 API
                  │
      资料元数据服务 ───── 私有 R2 原文件与文本
                  │
      持久化任务与可恢复后台消费者
                  │
      格式适配器 → 文本版本 → 用户检查
                  │
      受控资料分析 Provider / 手动结构化录入
                  │
      提取结果校验 → 用户确认 → 技能映射
                  │
        私有 PlanningContextVersion
                  │
      已验证岗位蓝图 + 学习单元注册表
                  │
       路径构建 → 时间排程 → 版本与差异
```

| 模块 | 输入 | 输出 | 依赖与限制 |
| --- | --- | --- | --- |
| DocumentService | 会话、文件或文本、资料元数据 | 资料及版本 ID | 所有者校验、D1、R2；不执行模型分析 |
| TextExtractor | 私有资料版本 ID | 带位置的文本版本 | 有资源上限的格式适配器，无外部网络 |
| DocumentAnalysisProvider | 已允许发送的文本、资料类型、输出契约版本 | 结构化候选 | 独立模型策略、预算和隐私路由；无搜索工具 |
| ExtractionValidator | 候选、片段索引、字段契约 | 合法候选或问题清单 | 不将模型输出视为可信命令 |
| ConfirmationService | 候选、用户修改、预期版本 | 不可变确认版本 | 乐观并发校验，保留修正来源 |
| SkillMapper | 确认条目、已有岗位蓝图 | 技能映射及未覆盖项 | 版本化别名和映射规则 |
| PlanningContextBuilder | 目标、选定版本、自评和约束 | 私有规划上下文版本 | 服务端重新校验全部关联 |
| Planning engine | 已验证上下文与注册表 | 路径、日程和候选计划 | 不读取原文，不直接调用模型 |
| ExplanationBuilder | 规划决策记录、可访问来源引用 | 解释与差异 | 使用结构化记录，不补写无来源事实 |

资料处理、模型分析和生成计划采用独立接口与任务，避免一次上传 HTTP 请求同时承担存储、解析、模型调用与排程。

### 9.1 现有模块的预期接入点

实施时需要局部扩展 Setup、规划契约、规划服务及版本指纹，不重新设计登录、Proof 或全局 Research。

旧请求不带个性化上下文时保持原语义；新请求携带 `contextVersionId`。新客户端和服务端必须一起校验上下文与蓝图、自评、时间输入一致，不能只加一个未验证的可选字段。

客户端预览与服务端最终生成使用同一版本化规则。若保存前任何依赖改变，返回版本冲突并重建预览，不能保存与用户刚确认的预览不同的计划。

## 10. 数据模型、存储与版本

以下是逻辑实体，允许在实施时以关联表和有界 JSON 组合实现，不要求每个概念都独立成为数据库表。

| 实体 | 核心字段 | 约束 |
| --- | --- | --- |
| `documents` | ID、ownerId、kind、displayName、currentVersionId、lifecycleState | 身份来自会话；归档不等于删除 |
| `document_versions` | documentId、version、objectKey、内容指纹、格式、字节数、createdAt | 原文不可原位覆盖；objectKey 仅服务端可用 |
| `document_text_versions` | documentVersionId、解析器版本、文本对象、片段索引、用户编辑来源 | 记录确定性提取文本与用户允许发送的文本版本 |
| `document_jobs` | ownerId、任务类型、输入版本、状态、租约、重试次数、请求状态、预算引用 | 不将正文或外部密钥写入任务消息 |
| `document_extractions` | jobId、文本版本、字段候选、片段引用、模型及契约版本 | 每次分析独立记录，失败候选不进入规划 |
| `document_confirmations` | 提取版本或手动来源、确认条目、用户修正、revision | 只追加；保留用户补充与原文事实区别 |
| `goal_document_links` | ownerId、goalId、documentVersionId、confirmationId、用途、enabled | 同所有者关联；每目标仅一个启用主 JD 和主简历 |
| `planning_context_versions` | 目标、依赖清单、确认事实、映射、策略版本、私有指纹、状态 | 不可变输入快照；删除资料可使其失效 |
| `document_processing_consents` | ownerId、文本版本、处理用途、隐私政策版本、允许时间 | 必须对应实际发送版本和允许的处理范围 |
| `document_deletion_jobs` | 删除范围、待清理引用、完成状态、有限错误码 | 可重试清理，避免只删元数据留下原文 |

### 10.1 存储分工

- R2：原文件、提取正文、用户允许发送的文本版本，以及超过结构化记录上限的私有内容。
- D1：所有者、状态、版本关系、确认结果、任务记录、规划依赖和有界结构化字段。
- 每类 JSON 写入前限制 UTF-8 字节数、数组长度与字段长度，不能把整个资料库塞进一行。
- 可复用当前 R2 绑定，但资料使用独立前缀、资料专用服务与访问检查；不复用公开 Proof 分享路由。
- 缓存和去重限定在同一所有者范围；不向其他账户暴露是否存在同内容文件。

### 10.2 版本锁定

计划生成时固定：资料版本、发送文本版本、确认版本、映射版本、蓝图/注册表版本、规划策略版本、自评、时间约束及相关事件状态。

版本指纹必须覆盖实际参与规划的输入。不同文件名但内容相同可以复用同用户解析结果；用户修正、切换 JD、修改映射或策略升级均产生新上下文，不能命中旧规划缓存。

回放使用已保存的结构化快照，不重新请求模型。新模型版本也不能静默重写旧确认结果。

## 11. API 设计建议

下表为接口职责草案，不是已实现接口。所有私有接口必须执行会话鉴权、同源/CSRF 防护、限流、所有者校验和统一的错误响应。

| 方法与路径 | 用途 | 关键输入与返回 |
| --- | --- | --- |
| `GET /api/documents` | 分页列出资料 | 返回安全元数据，不返回原文和存储键 |
| `POST /api/documents` | 上传文件或提交文本 | mutationId、类型、文件/文本；返回资料、版本与提取任务 ID |
| `POST /api/documents/{id}/versions` | 替换资料 | 预期当前版本、mutationId、新文件；返回新版本 |
| `GET /api/documents/{id}` | 查看资料详情 | 返回所属用户可访问的版本、状态与关联 |
| `GET /api/documents/{id}/versions/{versionId}/content` | 私有读取原文或提取文本 | 检查资料和版本关系，按需返回内容 |
| `POST /api/documents/{id}/analysis` | 启动模型分析 | 发送文本版本、处理同意记录、mutationId；返回 jobId |
| `GET /api/document-jobs/{jobId}` | 查询处理状态 | 返回有限阶段、错误码及结果引用 |
| `POST /api/document-jobs/{jobId}/cancel` | 请求取消 | 标记取消，阻止后续结果生效；不承诺退还上游费用 |
| `POST /api/document-jobs/{jobId}/retry` | 明确重试可重试任务 | 校验原任务、预算和请求状态，生成受关联的新尝试 |
| `POST /api/documents/{id}/confirmations` | 保存修正或手动字段 | 预期确认版本、条目和 mutationId；返回新确认版本 |
| `PUT /api/planning/document-selection` | 设置当前目标资料 | goalId、预期版本、资料/确认版本列表 |
| `POST /api/planning/contexts` | 构建私有规划上下文 | goalId、预期目标版本；返回 contextVersionId 及问题清单 |
| 扩展 `POST /api/planning/generate` | 生成方案 | 增加 contextVersionId，保留旧输入兼容路径 |
| `DELETE /api/documents/{id}` | 删除资料 | 明确删除范围，返回持久化删除任务 ID |

上传、分析、确认和生成分别幂等。同用户同 mutationId 的不同请求体应返回冲突，不能覆盖已有操作。

建议状态码：异步受理 202；已完成读取 200；版本冲突 409；不可用字段或无效内容 422；过大文件 413；不支持格式 415；限流 429。不存在或不属于当前用户的资源统一返回 404，避免泄露他人资源信息。

## 12. 后台任务、恢复与费用

### 12.1 独立状态维度

不使用一个状态同时表示上传、分析、确认和删除：

| 维度 | 建议状态 |
| --- | --- |
| 资料生命周期 | active、archived、deleting、deleted |
| 文件提取任务 | queued、extracting、ready、failed、cancelled |
| 模型分析任务 | awaiting-consent、queued、analyzing、validating、ready、failed、outcome-unknown、cancelled |
| 确认结果 | draft、confirmed、superseded |
| 规划上下文 | ready、superseded、invalidated |

只有确认版本中的启用条目可以进入正式上下文。解析失败、待确认或已删除资料不能参与生成。

### 12.2 持久化执行

任务先持久化，再可靠投递给后台消费者；使用 outbox 或等效恢复机制，解决“数据库记录成功、队列发送失败”的间隙。消费者以原子状态转换取得租约，写入结果时检查任务代次及资料生命周期，阻止过期消费者覆盖新结果。

任务消息只包含任务 ID 与最少路由信息。消费者通过服务端权限范围读取资料，浏览器轮询只用于展示状态，不负责推进业务执行。

拟优先评估 Cloudflare Queues：官方提供重试及死信队列机制；超过重试上限的消息在没有死信队列时可能被删除，因此终态不能只依赖队列中的消息是否还存在。[重试机制](https://developers.cloudflare.com/queues/configuration/batching-retries/)；[死信队列](https://developers.cloudflare.com/queues/configuration/dead-letter-queues/)

当前 Sites 项目没有已验证的队列接入证据。实施前必须验证消费入口、部署方式、权限和资源上限；若当前运行环境不支持，应接入可恢复的独立后台执行服务，或暂时保留手动录入并关闭文件自动分析入口。不能以延长一次 HTTP 请求的超时时间代替后台可靠性。

### 12.3 重试边界

- 文件读取等无外部付费副作用的临时失败可以有限重试，首版默认最多 2 次重试。
- 格式错误、密码保护和超限不自动重试，返回可执行的修复提示。
- 模型调用发出前记录请求阶段与预算预留；重复消息不能直接再发一次模型请求。
- 请求可能已经发出但结果丢失时，进入 `outcome-unknown`，保留保守预算占用，优先对账；不能承诺跨外部服务的“恰好一次调用”。
- 首版不自动调用模型修复输出；结构或引用不合格时提示手动修正，或由用户明确发起一次新的受预算控制分析。
- 用户取消或删除资料后，迟到的模型结果不能重新创建资料或激活上下文。

### 12.4 模型成本

资料分析配置独立任务标识、功能开关、身份/资格门槛、用户额度、全站预算及每次输入输出上限；不自动继承联网 Research 的开启状态或既有单次调用许可。

首版每份资料每次分析最多一次外部模型请求。超出所选模型输入预算时要求减少内容，不悄悄分成多次付费请求。

具体模型、token 上限和费用封顶值在运行时可行性验证后形成版本化配置，正式开启前必须完整配置；任何预算字段缺失时拒绝付费调用，手动录入保持可用。此处不提供未经模型与平台验证的固定费用承诺。

计划重排优先复用已确认结果，由确定性引擎完成，不重复调用资料模型。

## 13. 隐私、文件安全与删除

### 13.1 私有边界

- 所有资料、确认结果和个性化上下文均默认私有，公开 Profile 不读取这些实体。
- 资料所有者由服务端会话确定，不接受客户端选择 ownerId 或传入 R2 objectKey。
- 所有派生记录的关联都验证同一所有者；只在列表页过滤用户是不够的。
- 联系方式、精确住址等无关信息不进入规划字段。用户可以保留原文件，但模型输入与计划快照仅包含必要内容。
- 删除联系方式后，职业经历仍可能识别个人，界面不能承诺完全匿名。
- 日志只保留任务 ID、有限错误码、阶段、耗时、字节数、模型标识与费用状态；不记录原文、文件名、提示词、模型原始正文或私人链接。

### 13.2 外部处理与提示注入

发送前展示处理用途和待发送文本，允许用户修改或选择手动录入。允许记录绑定实际文本版本、用途及隐私政策版本；新资料或超出原范围的新用途需要新的有效允许记录。

资料分析关闭联网搜索、插件及任意工具执行。文档中的“忽略系统要求”“访问某链接”等文字只作为资料内容。上传内容不能决定系统提示、模型端点、预算、用户身份或存储路径。

如果采用 OpenRouter，应限制到符合隐私要求的端点，并在没有符合条件的端点时停止调用。官方 ZDR 控制适用于推理端点路由，不覆盖额外启用的搜索插件等第三方工具；不能仅打开 ZDR 就宣称整个处理链路零留存。[OpenRouter ZDR 文档](https://openrouter.ai/docs/guides/features/zdr)

### 13.3 文件安全

服务端同时校验类型、文件特征和实际读取字节数，不只相信扩展名或 Content-Type。解析器在有 CPU、内存、解压及执行时限的环境中运行，不执行宏、嵌入脚本或外部关系请求。

Markdown、文本及提取结果按安全文本渲染，不直接执行原始 HTML。私有下载使用合适的内容类型、下载头和 `nosniff`，不把 R2 私有对象暴露为公共可访问 URL。

第三阶段若增加 JD 链接抓取，必须单独设计 HTTPS、私有地址阻断、重定向复检、响应上限和超时机制；不能自动抓取模型从简历中发现的地址。

### 13.4 保留与删除语义

| 用户操作 | 行为 |
| --- | --- |
| 从当前目标取消使用 | 停止未来上下文选择；资料库和历史计划保留 |
| 归档资料 | 默认选择器隐藏；不宣称已经删除 |
| 彻底删除资料 | 立即撤销访问并停止任务；异步清理原文、文本、候选、确认、私有缓存及上下文中的资料派生字段 |
| 删除资料并删除关联计划 | 额外清理用户选定的派生计划；保留范围由删除界面明确列出 |
| 删除账户 | 纳入账户级清理流程，不因 D1 行删除就推定 R2 字节已删除 |

资料版本与上下文在正常生命周期内不可变，但彻底删除优先于重现能力。包含已删除资料的上下文标记失效并清理个人派生内容，保留不含原文的删除墓碑，不能为了回放永久保留简历摘要。

若用户选择保留已有计划，则保留其可执行日程作为私人派生内容，同时清理嵌入的资料原文、个人经历解释和失效引用。界面说明该计划仍可能反映此前选择的学习目标；要移除这些派生结果，需要一并删除计划。此类计划不再支持按旧资料快照重现，下一次重排必须使用有效输入。

删除操作只有在所有在线存储和派生内容清理完成后显示“已完成”；失败保持可重试状态，不显示虚假的成功。建议清理服务目标为 24 小时内完成并对超时告警，正式上线前用实际环境验证。历史备份的保留周期必须按实际托管能力披露，不能承诺即时删除所有备份；恢复备份时应重新应用删除墓碑。

首版建议清理未完成上传 24 小时以上的临时对象、失败且未保存的提取中间对象；已保存资料保留至用户删除，并计入账户配额。

## 14. 错误处理与可继续路径

| 场景 | 用户可见说明 | 系统动作 | 用户后续路径 |
| --- | --- | --- | --- |
| 文件格式不支持 | 当前支持的格式及大小限制 | 不创建可分析版本 | 导出受支持格式或粘贴文本 |
| 文件损坏/密码保护 | 无法读取及原因类别 | 保存失败任务，不泄露解析内部错误 | 重新导出、解除密码后重传 |
| 扫描 PDF 无有效文本 | 当前需要可选择文字的文件 | 不把空文本交给模型 | 粘贴内容；OCR 后续支持 |
| 文本过长 | 显示超限及可选择范围 | 不静默截断或多次调用 | 缩小到相关经历与要求 |
| 提取顺序可疑 | 提醒核对正文顺序 | 保留原文件和文本片段 | 手动调整文本后分析 |
| 某份补充资料失败 | 明确是哪份未参与方案 | 其他资料保持可用 | 移除该资料继续 |
| 模型输出不合法 | 未得到可用分析结果 | 不保存为确认事实，不自动修复付费 | 手动录入或明确重试 |
| 模型请求结果不明 | 显示尚未确认结果，不伪造费用 | 保守预留、对账、禁止盲目重发 | 等待状态更新或手动继续 |
| 模型开关关闭/额度不足 | 当前无法自动分析 | 不调用 Provider | 手动确认字段，使用已有蓝图 |
| 文档或确认版本冲突 | 信息已在其他页面更新 | 拒绝覆盖，保留用户草稿 | 加载新版本后重新确认 |
| 关键 JD 要求未覆盖 | 列出未覆盖要求 | 只能生成已覆盖范围的路线 | 接受部分范围或等待补齐 |
| 截止日期不足 | 显示延期项与预计时间 | 不压缩到不可能的时长 | 延长期限或明确缩小范围 |
| 删除清理失败 | 正在清理，可查看状态 | 撤销访问，后台继续有限重试 | 不要求重新上传或重复删除 |

错误状态必须与成功状态同等可恢复。刷新、退出页面或网络中断后，已持久化的资料和任务状态仍可读取；不能用浏览器内存作为唯一状态来源。

## 16. 分期交付与依赖

### 16.1 阶段 0：运行环境和契约可行性

目的：在开发完整交互前确认技术路径可运行。

交付内容：

- 使用合成文件验证中文、英文、双栏 PDF、DOCX 表格提取及资源上限。
- 验证解析器是否适配当前执行环境；复杂解析移至受限后台执行环境时明确接口。
- 验证持久化任务消费、部署、恢复、取消与 R2 清理能力。
- 固定资料模型的字段契约、隐私路由及预算策略；模型选择依据合法字段率、来源正确性、延迟和成本样例。
- 定义规划上下文及私有资料引用契约，评估与现有版本回放的兼容性。

完成条件：关键能力均有验证结果及可行路径。具体模型调用、云资源开通和发布不由本设计文档自动授权。

### 16.2 阶段 1：最小可用闭环

交付内容：

- 基础私人资料列表、上传、粘贴、版本、删除，以及 PDF/DOCX/TXT/Markdown 提取。
- 简历和 JD 结构化分析、手动录入、来源定位、用户确认及冲突处理。
- 当前目标选择资料；一次最多 1 份主简历、1 份主 JD、3 份补充资料。
- 映射已有合法技能，明确展示未覆盖要求。
- 确认信息影响技能审计、现有任务选择、优先级和范围；复用确定性排程。
- 保存上下文版本，展示计划依据；跳过导入和模型不可用时保持原流程可用。
- 将资料变更标为需要重新生成；首版只允许新计划预览和明确切换，不承诺局部自动重排。
- 权限、删除、任务恢复、预算与不明结果处理随首版一起交付。

完成条件：用户能从“导入简历 + 粘贴 JD”完成“核对 → 差距 → 可执行计划”，且方案变化可追溯，不出现越权读取或未经确认的能力升级。

### 16.3 阶段 2：复用与持续调整

交付内容：

- 多目标管理和并列方案比较，每个目标保留独立资料选择。
- 简历/JD 版本差异、过期提示和确认结果继承规则。
- 面试反馈专用结构及局部补强建议。
- 资料变更触发候选重排，保留完成历史，复用接受/放弃差异流程。
- 处理用户学习事件与资料更新同时发生的版本冲突。

完成条件：更新资料能解释地改变剩余安排，已完成工作不重复、不丢失，拒绝候选不影响当前计划。

### 16.4 阶段 3：扩大资料能力

按真实使用需求分别增加 OCR、公开 JD 链接读取、长资料检索和目录外技能研究。每项扩展独立确认质量、权限、费用及运行时边界，不作为首版前置依赖。

只有资料数量、长度或问答需求确实超出结构化方案时才引入 RAG。检索必须先限定用户及目标，再召回片段；资料删除时同步清理索引。检索结果仍是资料来源，不能绕过字段确认和规划验证。

不在尚未验证运行环境和模型表现时承诺固定开发天数。阶段 0 完成后，再按实际任务拆解估算投入。

## 17. 验收标准与评估样例

### 17.1 功能和解析

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| F01 | 支持格式 | 声明支持的样例可提取；不支持格式给出可操作提示 |
| F02 | 复杂排版 | 中英文、双栏、表格和项目列表可核对；不得把错序文本静默当正确事实 |
| F03 | 上传与模型分离 | 未允许外部处理时，任何文件提取路径都不会发送正文给 Provider |
| F04 | 来源定位 | 每个文件提取候选均能定位同用户同版本的原文片段 |
| F05 | 人工修正 | 用户修改优先参与当前规划，原提取结果仍可区分 |
| F06 | 缺失与冲突 | 未提及技能不会直接变成能力缺口；高影响冲突未确认前不生效 |
| F07 | 资料选择 | 未选中、已禁用、未确认或已删除资料不进入本次上下文 |
| F08 | 单资料失败 | 某份失败不会破坏其他资料或既有计划 |

### 17.2 规划与版本

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| P01 | 行为变化 | 至少一个固定样例因确认的简历/JD 信息改变任务类型、顺序或范围 |
| P02 | 依赖与时间 | 个性化优先级不能绕过前置依赖或突破每日/每周预算 |
| P03 | 真实性边界 | 导入不会自动授予 independent、verified、公开 Proof 等状态 |
| P04 | 未覆盖要求 | 目录外技能清楚显示未覆盖，不伪造完整路径 |
| P05 | 重现 | 相同已锁定上下文、策略和事件输入生成相同确定性结果 |
| P06 | 并发 | 确认或目标版本改变后，旧预览不能直接提交成功 |
| P07 | 更新 | 第二阶段接受候选前，当前计划与完成记录保持可用 |
| P08 | 删除 | 已失效上下文拒绝重现或生成，不能从缓存恢复被删除资料 |
| P09 | 兼容 | 不带资料的旧请求及匿名样例保持既有有效行为 |

### 17.3 隐私与恢复

| 编号 | 验收项 | 通过标准 |
| --- | --- | --- |
| S01 | 跨用户访问 | 读取、确认、下载、关联、任务查询、删除均拒绝跨所有者请求 |
| S02 | 公开边界 | 私人资料不能通过 Proof 分享、公共缓存或公开接口访问 |
| S03 | 日志 | 合成敏感标记不出现在业务日志、错误响应及运维面板 |
| S04 | 恶意内容 | 提示注入、HTML、外部关系链接、伪造 MIME 和压缩超限不会突破边界 |
| R01 | 重复请求 | 幂等键和重复队列消息不会重复激活结果或盲目调用模型 |
| R02 | 任务恢复 | 进程退出、投递失败、租约过期和页面刷新后仍能恢复真实状态 |
| R03 | 结果不明 | 外部请求状态不明时不自动释放全部预算或重复付费调用 |
| R04 | 删除竞态 | 删除/取消后到达的解析和模型结果不能重新生效 |
| R05 | 清理失败 | R2 清理失败可观察、可重试，不提前显示彻底删除成功 |

### 17.4 方案质量评估

建立版本化合成样例集，覆盖无资料、简历单独、JD 单独、简历与 JD、相互冲突、未知技能和非学习型要求。至少包含 React 已有经历、SQL 必备缺口、团队经历被误判独立能力、JD 必备/加分措辞混淆等关键案例。

对同一目标分别生成无资料基线与资料增强方案，由评审者检查：

- 关键 JD 要求是否被正确提取并分类。
- 缺口是否由确认信息支持，而非模型猜测。
- 不必要的重复学习是否减少。
- 依赖、时间和可执行性是否保持。
- 调整依据是否真实、具体并可回到原文。
- 未覆盖范围是否被明确告知。

固定关键案例必须全部满足预期规则；统计字段准确率、用户修改率、任务失败率和耗时分布，用实际样例形成后续目标。不凭设计文档声称“准确率达到 95%”或“用户效率提升 30%”。

质量观测原则上使用聚合计数和合成样例。收集用户纠错数据或人工查看私人原文用于质量评估，需要另行明确数据使用范围，不能默认由管理员读取。

## 18. 上线、兼容与回退设计

数据库采用增量新增实体及有版本契约的关联，不把既有个人学习记录批量转换成资料，也不自动导入浏览器数据。

建议新增资料管理、资料分析、资料个性化三个独立能力开关，名称在实施时确定。匿名样例不要求登录或模型密钥，文件导入关闭时原有 Setup 仍可使用。

上线顺序：

1. 完成阶段 0 的解析及后台可行性验证。
2. 使用合成文件和假 Provider 完成整个数据链路、权限及故障测试。
3. 验证迁移、私有 R2 访问、删除及旧接口兼容。
4. 在明确允许的范围内验证实际模型字段质量、隐私路由和费用记录。
5. 小范围开放，观察失败类型、用户纠错、耗时、费用及清理状态。
6. 满足首版验收后再扩大可用范围。

回退优先关闭新上传或分析入口，保留已保存资料的读取、删除及已有计划的查看能力；不能通过删除表或回退到不识别新上下文格式的版本造成计划不可读。

资料分析开关关闭时，应停止新的 Provider 调用并处理在途任务。资料个性化关闭时，已有日程仍可查看和继续记录学习，新的生成使用明确支持的输入路径；不得把无法读取的个性化计划静默替换为通用计划。

只有确认后向用户展示的功能才开放入口。队列、解析或模型准备不完整时保留手动路径，不能展示实际上不可完成的上传分析流程。

## 19. 设计决策与实施前验证清单

### 19.1 本草案采用的默认决策

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 资料保存方式 | 私人资料库、目标显式选择 | 便于复用并防止无关资料混入 |
| 首版目标 | 一次一个主 JD，不合并多家公司 | 保持要求、优先级和解释清晰 |
| 信息处理 | 先提取文本、允许发送、模型候选、用户确认 | 明确存储与外部处理边界 |
| 能力判断 | 经历线索与自评/Proof 分开 | 避免简历措辞自动变成能力认证 |
| 规划主链路 | 结构化私有上下文 + 确定性引擎 | 可验证、可重现、可解释 |
| 新技能 | 先列未覆盖，再受控补齐 | 防止输出不完整而伪装完整的路线 |
| 模型调用 | 独立处理策略，首版不自动修复或盲重试 | 便于限制费用与隐私范围 |
| 更新行为 | 版本化结果、候选方案、明确应用 | 保护用户正在执行的计划 |
| 删除 | 删除优先于历史重现 | 避免不可变快照永久保留私人资料 |
| 向量检索 | 后续按需要引入 | 控制首版复杂度 |

### 19.2 必须通过实际验证才能定稿的技术选择

| 项目 | 需要的证据 | 未通过时的路径 |
| --- | --- | --- |
| PDF/DOCX 解析器 | 目标运行环境的兼容性、资源限制和样例结果 | 更换适配器或使用隔离后台环境 |
| 持久化任务 | 托管部署、消费入口、可靠投递和恢复验证 | 独立后台服务；不支持时关闭自动分析 |
| 资料分析模型 | 字段质量、来源正确性、隐私路由及成本样例 | 更换模型或保留手动结构化录入 |
| 预算及输入上限 | 模型实际限制、费用配置和压力验证 | 缺配置拒绝付费，不自动扩大限制 |
| 资料清理与备份保留 | 托管存储实际能力、删除演练和恢复流程 | 不开放缺少可执行清理方案的保存能力 |
| 个性化兼容 | 旧请求、新上下文、回放和回退验证 | 保留旧流程，限制新功能开放范围 |

这些是工程验证事项，不代表需要用户逐项审批技术细节。进入源码实施、付费验证或部署仍按用户届时明确授权的范围执行。
