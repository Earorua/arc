# Arc v8 Task15 isolated cloud smoke design

2026-09-20. Design only, prepared from accepted local sources and `task15-operational-preflight.md`. No account, plan, deployed resource, route, or secret availability is assumed. Task14 is locally complete; this document neither completes Task15 nor authorizes a paid Provider request.

## Recommended composition

Build a separate smoke artifact that imports the **unchanged production `ResearchWorkflow` and executor Worker**, replacing only their import of `runtime.ts` with a smoke wrapper at build time. The wrapper calls the original runtime factories with mandatory synthetic Provider and service-binding bridge transports. Deploy two isolated Workers, two empty D1 databases, one private R2 bucket, one Workflow binding, and the executor's existing one-minute Cron. No Site production binding, Provider key, OAuth implementation, learning UI, or general administration framework is needed.

The second Worker hosts the real `createProductionSiteBridgeHandler` against the empty Site-shaped D1. Bridge requests still use the accepted HMAC, nonce, audience, size, deadline, and fixed-path checks. Service bindings carry these short requests between the two Workers. A bounded timer inside the injected Provider transport holds the **actual OpenRouter adapter call** open for 19 minutes 30 seconds, including a delayed response body. It never calls network fetch.

| Choice | Evidence and tradeoff |
|---|---|
| **Exact-module runtime alias, recommended** | Exercises the accepted Workflow class, event/reference guards, `research-once` step, zero retry/21-minute policy, `runResearchJob`, real adapter, storage and maintenance. Requires a small, fail-closed build resolver and explicit bundle verification. |
| Separate smoke Workflow/entrypoint | Easier dependency injection, but duplicates or omits Workflow guards and delivery behavior; green results do not establish that the production Workflow composition ran. Do not select while the existing runtime override suffices. |
| Synthetic Provider over another service-binding handler | Adds a real long-lived internal HTTP request. It can test that Cloudflare-specific internal connection, but still does not establish OpenRouter or public Internet HTTP survival. Adds a transport and platform limit question without being necessary for the required Workflow-lifetime proof. Keep out of the first candidate. |

A sleep-only step, `step.sleep`, fake clocks in the deployed long case, or Miniflare `outboundService` in place of a deployable transport does not satisfy this design.

### Fail-closed build contract

Resolve the exact canonical `worker/research-executor/runtime.ts` module only when imported by the accepted `index.ts` or `workflow.ts`; redirect those edges to the smoke wrapper. Permit the wrapper's explicit import of the original runtime as the sole bypass. Reject unexpected importers, missing/extra matches, cycles, or absent required exports. Do not use a broad `runtime` alias or environment-selected production behavior.

The wrapper always supplies both transports, with no global-fetch fallback. It projects only required binding/configuration fields and supplies a compile-time noncredential sentinel for the adapter's key syntax check; the deployed environment has no `OPENROUTER_API_KEY` secret. Synthetic Provider transport accepts only the adapter's exact POST target and fixed Kimi request shape, including low/32768, privacy settings, search caps, and no Repair. Unexpected URLs, redirects, methods, bodies, missing bindings, or unrecognized scenarios fail before network activity. Bridge routing accepts only the configured peer origin and existing method/path allowlists, and calls the named peer service binding directly.

Record build metafiles, source hashes, alias edges, exports, policy assertions, and artifact hashes. Hash-check production Workflow/runtime/policy/adapter sources against the reviewed inputs. Inspect the smoke graph for every outbound-capable call: the Provider path ends in a local synthetic function; bridge paths end in only the two named service bindings. Existing unused default-fetch branches inside reused source are not an egress proof by themselves. Negative tests must exercise the actual built entrypoints with global fetch throwing. Deploy the verified prebuilt artifact; the Wrangler entry/build configuration must not bypass the alias by independently rebuilding the source entry. Separately verify the production build has no smoke entry, transport, control path, fixture, or migration input. Keep the existing production build script/output untouched.

## Protected seed/control and ownership

Expose only fixed `POST /_smoke/start` and `POST /_smoke/status` on the smoke Site Worker. Reuse `signBridgeMessage`, `verifyBridgeMessage`, `readBridgeBody`, and `D1BridgeNonceStore` with a **separate smoke-control key ID/secret**, fixed audience/path/method and `jobId: collection`; sign responses as well. Cap control bodies/responses at 4,096 bytes and use the existing guarded D1/`PublicOperationScope` machinery for bounded seed work. This reuses the accepted protocol rather than inventing a token/session scheme. Direction is a fixed protocol field, not a claim that the operator is a production executor. Control credentials must be distinct from both bridge directions and absent from output/logs/browser storage. Reject Origin-bearing requests, unknown paths, replays, unsigned/oversized requests, and attempts to supply owner, endpoint, policy, SQL, delay, or arbitrary job IDs.

The body selects one fixed scenario ID. Server-side fixture identity maps that ID to synthetic owners, a stable mutation, and a UUID job ID. Use the repository's existing `createJobId` injection for the fixture; maintain stable IDs across ambiguous responses. Seed only synthetic user/cohort rows, then call `createRemoteOrReplay` and `SiteAdmissionCoordinator.admitNew`; do not fabricate admitted/claimed/grant/Ready rows. Use the exact accepted production configuration fingerprint. Each fixed scenario has a distinct synthetic owner and stable mutation/job ID to isolate quota. Research package cache lookup is global across owners, so also use three distinct fixed role inputs: Data Product Manager, Senior Data Product Manager, and Lead Data Product Manager, respectively. Clone the accepted synthetic candidate with the corresponding role name/id; retain skills/resources/annotations and require all three variants to pass the actual validator locally. Distinct normalized role keys prevent cross-scenario cache hits; owner separation alone does not. Do not append a scenario namespace to production policy/fingerprint fields. This seed control tests repository/admission behavior, not the public session route.

After admission, perform the normal signed submit/bootstrap/accepted path with a bounded control request. If its response is lost, status/recovery uses the same mutation/job; Cron owns any resubmission. Persist the mapping before external submit. Return `backgroundAccepted` only from the real stored accepted proof. Run one active scenario at a time; durable scenario bookkeeping associates Provider effects with that scenario and prevents overlapping fresh starts. Repeated start/status cannot create a new job or extend deadlines.

The control principal owns the fixture suite; it cannot choose a real user. Status returns bounded hashes, timestamps, counts and safe state, never candidate body, secret, R2 URL, or unrestricted database rows. Owner-A reads must resolve the original run; a fixed owner-B lookup must reveal none of it. This establishes repository owner isolation, not real OAuth/session authentication. The operator driver uses a separately configured smoke-control credential through the parent task's secure configuration path; it must not scrape Wrangler OAuth or application secrets.

## Cloud cases and independent recovery

Run targeted local RED/GREEN checks before cloud deployment. The minimum cloud suite is three fixed cases:

1. **Long success.** The injected fetch validates/counts one request, waits 1,140,000 ms before returning headers, then finishes a bounded JSON response stream 30,000 ms later. Both waits honor the adapter's AbortSignal and clear timers on completion/cancellation. Leave the production 1,200,000 ms headers/body deadline and 1,260,000 ms execution lease unchanged. The actual step remains inside `runResearchJob`/`OpenRouterResearchProvider.research` throughout. Close the initiating browser/client after the short accepted response; do not poll, call recover, or keep an HTTP request alive during the wait. Obtain later state from a fresh process. Require recorded elapsed Provider wait at least 1,170,000 ms and below its real deadline; a delay over deadline is a failed long-success case, not grounds to enlarge policy limits.
2. **R2 committed, result fixation missing.** With a short synthetic response, the execution-only R2 wrapper lets the real conditional put succeed, writes a bounded fault marker, then throws before returning to `ExecutorReceiptStore.save`. The accepted source already turns this into an unavailable execution reference; it skips immediate Workflow delivery. Actual independent Cron must find the claimed job, validate the fixed R2 object, fix its D1 metadata and deliver to the real Site importer. Neither driver status nor a browser recovery call may repair the gap.
3. **D1 result fixed, Workflow continuation lost.** The execution-only receipt wrapper awaits real `save`, persists the fault marker and throws instead of returning its reference. R2 and immutable result metadata remain. Cron must deliver the same receipt and finish accounting with no second Provider invocation. Keep maintenance/HTTP readers free of the execution-only fault adapters.

For both fault cases, collect the observed boundary state before recovery where scheduling permits, the Workflow output, independently triggered Cron trace, original/final hashes and final ledgers. If Cron races the boundary inspection, do not claim that snapshot was observed; rely on the durable fault/effect markers and record the race, or rerun the scenario on fresh isolated resources. An additional fixed transient completion-response failure can show retry delivery if needed; it is not required to multiply cloud long waits. Faults are fixture-induced exceptions after durable effects, **not evidence of a real Provider, isolate, or infrastructure crash**.

After each case, repeat signed submit/get for the same job and owner recovery for the same mutation. Assert the request hash, job ID, original begin grant/deadline, receipt hash and terminal state remain stable. Read-only status must not invoke the importer or maintenance. Before using an owner-facing recovery method that can import, first prove Cron already completed the import.

Production executor status is also capable of repair: `http-routes.ts` calls `receipts.recover`, which can fix a missing D1 result from R2. Therefore do not use that endpoint to collect pre-Cron boundary evidence. The smoke Site status reads only its own bounded evidence; executor boundary snapshots use inventory-bound read-only D1/R2 operational queries. Preserve separate database bindings rather than giving the Site Worker access to executor D1. After Cron completion has been independently established, normal signed get/recover can be checked for idempotency.

Required local TDD covers alias escape/missing-binding/global-fetch rejection; distinct control/bridge keys and nonce replay; wrong owner/body/path/audience; fixed-scenario idempotency; duplicate dispatch CAS; real adapter headers/body shared deadline and cancellation with fake timers; each fault boundary and Cron repair; real Site validator/import accounting; and production bundle exclusion. Use the installed Workerd/Miniflare harness for the built smoke graph locally, with network interception only as an extra detector, never the cloud transport design. Retain accepted prior fault-matrix tests rather than rebuilding them all.

## Acceptance, retention, and cleanup

Save one bounded report with actual account/resource identifiers and deployment revisions, reviewed source/artifact hashes, migration versions, synthetic scenario IDs, invocation/Repair/unexpected-target counts, Workflow status/reference size, timestamps/latency, D1 dispatch/result/delivery/import state, matching R2 receipt hash, package/audit/quota/budget counts, Cron trace, and owner-isolation results. Expected per uncached case: synthetic Provider calls 1, Repair 0, real Provider egress 0 by reviewed composition, one accepted quota effect, one immutable result/package and settled synthetic usage. Label synthetic cost as fixture accounting, not an invoice or measured spend.

Observe the pre-acknowledgement receipt if available; after acknowledgement, production cleanup may replace its body with a tombstone, so a later missing body is not by itself a failed persistence test. Verify metadata/hash and deduplication identity remain and that normal Cron cleanup follows the accepted retention policy. Do not delete a job marker to rerun it. Disable new smoke starts after the suite, retain private evidence for review, then remove only inventory-confirmed smoke routes/resources/secrets. Stop active workflows before removing their dependencies. Resource cleanup must use the recorded isolation manifest, never a name-prefix guess or production identifiers.

This proves the deployed Workflow's long awaited adapter lifetime, persistent D1/R2 handoff, real signed Site import/accounting, and independent scheduled recovery without a browser. It does not prove external upstream HTTP survival, real model quality/charge, real OAuth, the deployed Sites application's route/domain behavior, or production backup readiness. Task15's protected Site deployment and the later task's login/learning/Proof/paid acceptance remain separate evidence.

## Root refinements before implementation

- Associate synthetic transport effects with the exact job returned by this invocation's real jobs.get. Keep this association in the invocation-local runtime closure, never a shared global or arbitrary client-supplied ID. Unknown/multiple/mismatching job identities reject before the synthetic effect; job/owner/scenario constraints remain durable.
- Fixed control paths reuse the accepted signature context schema (it permits /_smoke/start and /_smoke/status and collection). Require distinct key IDs as well as distinct secret bytes, because nonce scope includes direction/keyId. No production authentication protocol changes.
- Cloud timing uses unmodified Date.now and performance.now. Local tests may inject short fixed delays/fake timers only through an explicit local test composition; deployed build must hard-code the reviewed long durations and reject duration override input.
- Start exits after its bounded response. If acceptance is initially ambiguous, reconcile the same scenario until actual persisted acceptance, then exit the initiating process. Later status uses a fresh process; no client connection or browser poll keeps the long Workflow alive.
- Paired service-binding bootstrap needs an actual supported deployment order. Verify whether the platform accepts a target before it exists. If not, deploy isolated no-route 503 stubs for both recorded names first, then full reviewed bundles after bindings/resources exist. Stub artifacts must contain no Provider or data writes, and must never replace an existing non-smoke resource. This operational sequence is not evidence of full smoke success.
- If final cloud resource configuration is not available, local implementation/build accepts explicit synthetic local bindings only. Do not produce deployable JSON containing guessed account IDs, database IDs or placeholder secrets. Actual manifests are generated later from the verified isolation inventory.
- Isolated smoke success leaves real external HTTP/Research and protected Sites deployment as separate outstanding acceptance. It does not remove the production data-backup gate.
