## 修复的用户行为

1. **对应课程时保留原文。** 已确认的 UI token、关系建模、运行日志等词，可以在已验证的指定课程目录内按上下文对应已有技能。只保留 Figma、泛化组件或缺少语境时不会擅自推断课程；被移除的词不会从周围文字恢复。规则不会被其他 Research 岗位继承。
2. **逐词修改对应关系。** 同一条事实同时包含 React 和 UI token 时，修改或排除后一个词不会丢掉 React。空的显式选择表示本轮不映射；原事实仍保留。新请求不允许用旧的整条覆盖入口重写带有技能词的事实。
3. **教练建议和学习意向可实际参与排序。** 用户单独勾选“作为本轮学习重点”后，建议对应的已有任务获得软优先级；主 JD 的明确必备/加分要求优先。确认事实不会自动采用建议或修改能力自评。
4. **核对页面按资料来源表达。** 补充资料中的建议不再强迫用户选岗位必备/加分；高影响提醒仍需核对。预览展示逐词映射、未覆盖、明确排除及采用状态，计划解释分别说明经历和学习重点来源。
5. **选择变更使旧预览失效。** 修改资料、课程对应或学习重点后必须重新预览。来回切换、恢复失败、组件卸载后的迟到响应不会恢复旧可采用引用。同一输入下的网络重试仍使用幂等回执；用户修改选择后使用新 mutation。

新增选择只保存到服务端不可变上下文快照与指纹；没有把资料正文或这些选择加入浏览器持久 setup refs。没有增加数据库迁移。mapping / planning / explanation 版本分别为 `2026.11.5` / `2026.11.2` / `2026.11.3`；历史预览从原快照读取，不按新规则重算。

## 集成保护

独立的“仅教练建议”离线 HTTP 流程不混入经历事实来掩盖问题。它检查未采用时无变化、采用后合法排序、放弃与接受、选择版本过时、删除资料后的采用拒绝，以及原有 Proof、任务 ID/内容/工时/前置依赖、完成记录、能力自评和可用时间保持原有语义。

原先两个 Research 测试的默认并发本地连接问题仍为单独限制。分组执行通过不能证明默认并发稳定性已修复。

## 复审发现与处理

- 旧整条映射接口能覆盖已保留技能词，导致其他词消失。修复为新请求按词选择，旧快照仍可读。
- 上下文匹配最初可能借用另一子句、他人职责或否定语境的域词。独立审查和本机 Worker 反例均复现该问题；现要求技能词与域词位于同一个可肯定的子句，并保留中英文反例及肯定对照。跨逗号、混合否定等无法确定的关系继续显示未覆盖。
- `service`、重试、请求等普通词还可能把纸质客服日志或实验室样本测试解释成软件技能。现要求明确的软件、代码、API、运行时等技术依据；真实软件管理实验室样本的对照仍可映射，未直接按行业词禁用。
- UI 出现选择切换回来、恢复引用变化和离开页面后的旧预览残留。新增异步竞争测试，采用失效引用与请求身份双重检查。
- 旧记录带技能词及整条映射时，逐词 UI 曾误显示自动对应。现显示历史整条选择，包括不在当前候选列表中的原课程 ID，保持历史含义。
- 首次干净副本类型检查发现 Map 键推断和测试只读数组类型问题；已改正类型声明，没有放宽校验或修改生产判断。
