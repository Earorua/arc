## 用户行为与修复依据

1. **协助只适用于有证据的任务。** “我用 React 实现了原型，交互测试由结对伙伴协助”不再把后一项工作当作 React 实现的 guided 证据。同一个词出现在两个不同任务时，一个局部建议不能覆盖整条事实。
2. **事实与核对保留，提示可以为空。** 明确的个人能力、阅读范围或真实受指导实践可以产生单独核对提醒；无法给整条事实一个安全水平时保持空提示。个人简介标题只用于定位正文，完整引文及原词仍保留。
3. **不把共用技能词当作矛盾。** resume-12 的“能完成报表”和“复用导师提供的 SQL、只改日期参数”都保留。前者核对具体能力范围，明确的“本人是否编写查询待确认”标为信息缺失，不自动赋 uncertain、independent 或 verified。
4. **限定语不会在分句时丢失。** 示例、条件、转述及否定继续约束后续内容；明确真实的个人转折可以结束否定，但不能结束仍在生效的示例或转述。前段真实陈述也不会被后段转述吞掉。
5. **明确练习需求继续可核对。** 合法 constraint 中“尚未实践，且希望练习”保留核对、原类型和空提示。否定练习意愿、另一人的愿望、普通岗位要求和时间地点不会据此成为个人能力核对。
6. **界面表达缺失原因。** missing-information 显示“信息缺失或待确认”。确认事实仍不自动采用能力自评；本批没有新增 wire/schema 或数据库迁移，v1 提示词未改。

红例与中间修复按唯一标签保留。首次原因包括尾随协助被错误借给前项任务、逗号拆分丢失外层限定、转述检测跨越分句，以及候选类别守卫误删原有学习限制提醒。修复记录在本目录，未用清空提示、放宽来源或改写原 gold 获得通过。
