## 评分和复现

1. 对照固定摘要读取语料，检查每份输出的文档、文档版本及文本版本，拒绝缺份、重复或混入其他资料。
2. 使用生产提取校验器检查原始 `extraction`，用已知原文验证分段和引用。之后用现有质量评分器按语义字段、预登记的可接受表述、技能标签及原句一对一匹配。未登记的同义表述保留原始得分，供下一轮审阅。
3. 逐份要求关键召回率及适用的必备/加分分类准确率各至少 90%，保留的来源引用 100% 有效。多提或错配的事实、漏掉或多出的核对点、擅自判定冲突、自评越级均导致失败。要求普通样例可预填 3/3，边界样例符合各自预期 3/3。注入样例单独检查两处核对点，事实相关比例记为不适用。
4. 评分器只读取本地 JSON，报告只含固定样例和字段标识、分数及失败代码。它可以复核提取内容。真实运行的来源、路由、回执、账单和所有高影响核对点最终由谁确认，分别在采集、对账和用户核对环节验证。[本地评分入口](../../scripts/score-materials-supplements.ts) · [生产校验器](../../app/server/documents/extraction-validator.ts) · [一对一评分](../../tests/helpers/document-quality-evaluation.ts)

在工作树根目录运行以下离线测试，或用第二条命令对指定的本地合成输出评分。

```powershell
node node_modules/vitest/vitest.mjs run --config vitest.config.ts tests/server/document-supplement-quality.test.ts
node --import tsx scripts/score-materials-supplements.ts './captures/supplement-output.json'
```

输入对象含 `corpusSha256` 和 `outputs` 数组。每条输出含 `documentId`、`documentVersionId`、`textVersionId` 和未编辑的 `extraction`。`extraction` 使用生产契约的 `schemaVersion`、`items` 和 `reviewPoints`。输入须为不超过 1 MiB 的普通文件。命令退出码 0 表示评分通过，1 表示有项目未通过，2 表示输入或冻结语料无效。
