# 用另一家公司的 JD 调整学习路线

## 验收场景

同一位学习者用简历、A 公司的岗位 JD 和一份面试复盘创建路线，完成一项任务，随后引入 B 公司的同岗位 JD。第一次放弃 B 的建议，换一台设备再次选用那份已经核对的 JD，这次明确接受。最后在资料库里手动整理另一份笔记。

全程在本机运行实际的岗位设置、今日学习、路线页面及其 HTTP 服务。浏览器采用独立临时会话，数据库分别承载站点和执行器，资料存储、登录身份和工作流调度使用本机测试实现。四次分析由固定的合成回复提供，走实际签名、回执校验、提取、确认和规划代码。此记录验证产品流程。Kimi 的真实提取质量单独记在 [R2 验收报告](2026-11-06-materials-b2-r2-result.md)。

## 修复前后

| 用户操作 | 修复前的复现 | 修复后的验收 |
| --- | --- | --- |
| 创建路线前核对采用的资料 | 简历和 JD 显示在摘要中，已选择的补充资料只出现在事实预览里。 | 摘要逐份列出三类资料、确认状态和移除操作。只选补充资料也能检查，每份都可单独移除。 |
| 在新会话重新选用已确认的 B 公司 JD | 打开已保存的 JD 后，必须再点一次确认，才能看到采用按钮。 | 用户直接点“采用这个已确认版本”。系统复核当前文本和事实版本，采用这份 JD 新增的确认写入为零。编辑中或过期的确认无法复用。 |
| 确认过程中继续编辑 | 确认 SQL 的回复晚到时，可能将已经改成 Python 的事实标为已确认。路线进入待决定状态后，在途的采用操作也可能继续生效。 | 迟到的确认只更新同一份资料的修订号，新内容仍需核对。工作区锁定会使在途采用失效；解锁后只读恢复仍有效的确认。 |
| 放弃一次，再对相同 JD 生成建议 | 新的影响预览成功，两次生成请求都返回 HTTP 409。第二次提议使用了已放弃提议的候选 ID，触发资料提议表的唯一约束。 | 两次提议各自得到候选版本和回执，已放弃记录保留。重复提交同一请求仍可重放，过期预览和已有待处理建议仍有冲突保护。 |
| 接受或放弃后查看当前安排 | “调整建议已生成”的提示可能在放弃后继续显示。 | 提示跟随服务端的待决定版本。只有用户点击接受后，B 才替换 A。 |
| 查看历史或重试刚才的操作 | 历史曾将放弃标为待处理，已接受的提议会重复出现。另一项操作重用旧请求号，还可能拿到上次放弃的成功回执。 | 保存、放弃、接受各自有一条记录。相同决定可原样重试，换决定类型、候选版本或路线基线会返回冲突。资料提议还需匹配该接口自己的登记和请求摘要。 |
| 核对已学内容及人工整理 | 需验证计划替换保留学习成果，以及手动路径的独立性。 | 完成事件与已完成单元的摘要逐一相同，简历和补充资料的文档、文本及确认版本相同。手动保存、编辑、确认一份新笔记后，当前路线仍采用原来三份资料。 |

## 复核方式

- 先用修复前的页面重复“选择 B、生成、放弃、再次选择 B”。查看第二次预览与生成操作各自的 HTTP 状态。根因通过实际 SQLite 写入定位。修复保留数据库唯一约束。
- 使用修复后的页面将 A 的 PostgreSQL 必需要求、简历里的导师指导经历和 OpenTelemetry 面试复盘一起预览。删除 JD 建议中的 Vitest 技能词，原文中的优先项仍可查阅，删除的词不再进入技能映射。能力自评由用户单独核对。
- 在今日学习完成一个单元。在全新的浏览器环境打开同一测试账户，先检查原来三份采用记录，再引入 B 的 TypeScript 必需要求和 PostgreSQL 优先项。第一次保留当前安排后，A 仍生效。第二次在手机宽度采用同一 B 版本并接受，将两次候选编号、前后采用版本及完成记录作比较。
- 在资料库点“保存并手动整理”，添加一条事实并确认。核对模型替身和回执替身的调用数，同时逐个检查浏览器持久存储中是否出现合成资料的名称、正文或事实。

自动化回归覆盖打开期间的资料版本变化、别人的文档、已撤销确认、同一候选上的并发决定以及已删除资料的历史脱敏。没有裁决依据的旧提议显示“结果未记录”。[服务端确认测试](../../tests/server/document-confirmation.test.ts) · [资料提议与采用记录测试](../../tests/server/material-adopted-refs.test.ts) · [决定回执测试](../../tests/server/planning-service.test.ts)

## 兼容与发布边界

旧网页读取当前工作区、归档、决定结果和回执时继续使用原有事件结构。服务端保留用于区分两次资料预览的内部指纹，并能够重放既有旧事件。将来上线时，应先更新所有负责重放的服务实例，再开放新的资料提议写入。一旦产生带新指纹的事件，回滚功能可以关闭新写入，同时保留兼容这些事件的读取代码。

本轮只产生本机测试记录。没有新增 Kimi 费用、远程迁移或部署。已签发的 R2 已封存，24 份真实模型评测未达到质量门槛。P1 的四份诊断材料、费用上限及独立授权仍以[已冻结的 P1 单据](../superpowers/runbooks/2026-11-06-materials-b2-diagnostic-p1-authorization.md)为准。公开发布还需满足后续真实质量验收、上线授权和发布后核验。
