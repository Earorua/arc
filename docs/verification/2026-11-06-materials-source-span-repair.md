## 用户会看到的变化

- **有来源的预填事实。** 新 Kimi 策略只请模型选出事实类型、原文片段和需核对的问题。服务端在对应段中唯一定位引用，用原文生成可编辑事实。句末标点少抄一字时从原文补回。摘录删掉否定、归属或限定条件而形成句中残片时拒绝交付。按换行、名单项目和句子识别证据边界，模型对事实类别或技能的解释仍由用户核对。旧策略 24 个付费请求体逐字节匹配 R2 摘要。[生产适配器](../../worker/document-executor/provider-http.ts) · [来源解析](../../worker/document-executor/source-span-extraction.ts)
- **删除或确认技能词有效。** 离线集成用例从岗位 JD 抽出 `PostgreSQL`，用户保留并确认后，现有角色蓝图的受控别名将它对应到 SQL 必备项。用户移除的词和无原文支持的自评建议不会出现在后续规划中。旧草稿和确认版本可继续使用。补充资料重排保留已完成任务和事件。[用户路径测试](../../tests/server/material-confirmed-skill-labels.test.ts) · [核对界面](../../app/components/materials/material-confirmation.tsx)
- **只交付完整结果。** 即使聊天返回的 JSON 仍能解析，只要配对回执明确显示截断、取消或不完整，就保留可核对费用并将候选隔离。输出问题只记录固定类别。读到受保护 key 指纹时也不会把它当作可发送或持久化的 generation ID。OpenRouter 的聊天和 generation 响应均提供结束状态。[适配器回归](../../tests/server/document-source-span-provider.test.ts) · [回执隐私回归](../../tests/server/document-receipt-credential-privacy.test.ts) · [OpenRouter API](https://openrouter.ai/docs/api_reference/overview)
