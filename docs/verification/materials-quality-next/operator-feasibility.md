## 已确认的账户接口边界

普通推理 key 可通过 `GET /api/v1/key` 查询自身的 `limit`、`limit_remaining`、`usage`、有效预算、workspace 和到期字段。必须保留原始十进制金额，再作保守的整数费用比较；不能把历史已结算数当作当前余额。[当前 key 文档](https://openrouter.ai/docs/api/api-reference/api-keys/get-current-api-key)

账户 `GET /api/v1/credits` 的现行官方文档明确要求 **management key**，普通专用 key 的 403 不能解释为余额不足，也不能靠换用 Research 凭据解决。本轮只读查看现有 Credits 页面并刷新，页面提供的是按美分显示的余额，没有取得精确账户 Credits API 证据。[账户 Credits 文档](https://openrouter.ai/docs/api/api-reference/credits/get-remaining-credits)

最终入口采用两项分开的资金证据：普通 key 的精确剩余额度，以及新鲜账户 Credits 界面的**保守下限**。原 Gate／R2 规则要求两者覆盖费用预留，没有要求为了读取账户资金而创建管理凭据。界面显示两位小数时，只取向下的整数美元作为保守下限，明确记录显示精度、来源、时间、同一账户绑定和人工审阅的证据摘要；不能把显示值写成精确 API 余额。下限必须覆盖本轮合计授权范围，缺失、过期或账户不匹配时拒绝启动。此记录由启动包外部核验并固定，执行入口不能自行生成通过证据。

这一路径保留原费用上限和独立资金核验，不调用 management-only Credits API，也不创建管理 key、提额或充值。最终仍须在启动前刷新界面证据、隐藏输入查询实际 key 及其有效预算；当前并未通过精确 key 预检。公开授权单不保存账户标识、完整密钥或私有余额回执。
