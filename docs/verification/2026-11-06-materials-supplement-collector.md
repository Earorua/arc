# 六份补充资料的离线采集器验收

这项工作解决补充资料怎样验证真实提取质量。P1 只处理四份简历和 JD。六份补充资料有各自的来源和金标准，未来需要独立批准。以下所有补充资料回复和费用均由本地测试替身产生。

## 修复内容

原收集器限定旧版 Kimi 输出。仅放行新策略时，即使成功读取六份回复及回执，评分器仍把精简的来源片段 JSON 当成旧格式，六份均无法正确评分。现在，私有账本保留原始回复，并将生产适配器实际解码的结果绑定到同一份资料、费用回执和原始内容的摘要。解码拒绝时明确保存空候选，费用依已核验的回执结算。

独立复查还复现了两条会制造假通过的路径。一是改动存储中的策略名，把六个截断回复重新当旧格式评分。二是从导出的测试入口注入时钟、传输和假回执，再把结果标记为真实运行。修复后，评分重新核对运行开始时已核验的签发内容。测试入口只能标为 `offline-test`，正常的真实 CLI 使用实际时间、传输、固定账本和源码清单。在错误源码、伪造 Git 工作树、目录联接或会泄露私有凭据指纹的运行编号下都会拒绝。

## 独立固定回复对照

| 本机替身给出的情况 | 观察 |
| --- | --- |
| 六份完整、来源正确 | 6 次模拟 POST、6 次模拟 GET。3/3 普通样例可预填，3/3 边界样例通过。 |
| 六份均在 token 上限处截断 | 六个解码结果为空，普通 0/3、边界 0/3。六笔已知模拟费用仍结算。 |
| 截断后篡改账本策略名 | `issuance-mismatch`，停止并保留已结算费用，不产生通过结论。 |
| 首份伪造来源 | 只有受影响的资料失败，整批质量未通过。 |
| 首份费用不明 | 一次模拟 POST 和一次模拟 GET 后停止，保留 72,960 微美元的模拟预留，之后五份没有发送。 |

这 6 份固定语料在旧策略与新策略下使用不同配置摘要。按审阅设置每份顶格预留 0.072960 USD，六份合计 0.437760 USD。现有收集格式每份最多一次 POST、一次 GET。若需要再查回执，需在下一份单据明确新的读取边界。这里没有读取账户、登记真实账本、签发补充资料授权或发生实际费用。[独立合成测试记录](materials-supplement-quality/2026-11-06-collector-regression.json) · [两套配置的只读检查](materials-supplement-quality/2026-11-06-collector-inspection.json)
