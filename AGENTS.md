# Working on Arc

Read [SOURCE_INDEX.md](./SOURCE_INDEX.md) before choosing a checkout or resuming a task.

- Inspect `git status`, fetch `origin`, and compare the current branch with the latest `origin/master`. Start ordinary website work from the current application baseline. Preserve unrelated local changes when changing worktrees.
- Use the source index to distinguish the current application, the deployed release, and paused materials development. The newest timestamp or a folder named `ui-warm-precision` does not establish source authority.
- Materials work remains on the development branch identified in the source index. Its saved failures and unfinished work are not released features. A source backup does not resume a paused task or authorize deployment, migration, or paid model calls.
- Historical checkpoint instructions, frozen source copies, and scripts under archived evidence are reference material. Do not copy their application files over a newer implementation or rerun their deployment commands.
- Preserve the current English interface, mist/ink-teal palette, quiet workspace loading, and reviewed brand integration when reconciling other work. Check actual source and tests rather than relying on old README or release descriptions.
- When source ownership changes, update the source index and the relevant checkpoint in the same change. Keep the bilingual product READMEs concise; detailed source accounting belongs under `docs/source/`.
- Keep ordinary task branches temporary: start from fetched `origin/master`, verify and merge completed work, then delete the redundant branch and prune stale remote references. Preserve unfinished materials work on its designated branch. Historical worktrees may use detached HEAD; use their pinned commits or archive tags for reference, not as a current development baseline.
- Use `package.json` for runtime requirements and check commands. Record fresh validation for the actual changed source before claiming completion.
